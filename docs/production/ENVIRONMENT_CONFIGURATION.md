## 1. Overview

This document describes all environment variables required to run Sana HRMS in development, staging, and production environments. **Never commit real credentials to version control.**

### 1.1 Environment Files Structure

```
sana-hrms/
├── .env                          # Root environment (Docker Compose)
├── .env.example                  # Template for root
├── backend/
│   ├── .env                      # Backend runtime config
│   ├── .env.example              # Backend template
│   └── .env.test                 # Test environment (CI)
└── frontend/
    ├── .env                      # Frontend build config
    └── .env.example              # Frontend template
```

### 1.2 Configuration Hierarchy

```
Priority (highest to lowest):
1. Shell environment variables (export VAR=value)
2. Docker Compose environment: section
3. .env file in service directory
4. .env file in project root
5. Dockerfile ENV defaults
6. Application code defaults (configuration.ts)
```

## 2. Root Environment (.env)

**File:** `sana-hrms/.env`  
**Used by:** Docker Compose for variable substitution

### 2.1 Required Variables

| Variable | Description | Example | Required |
|----------|-------------|---------|----------|
| `POSTGRES_PASSWORD` | PostgreSQL superuser password | `s3cureP@ssw0rd!` | ✅ Yes |
| `JWT_ACCESS_SECRET` | JWT access token signing key (64+ chars) | `a1b2c3d4...` (base64) | ✅ Yes |
| `JWT_REFRESH_SECRET` | JWT refresh token signing key (64+ chars) | `e5f6g7h8...` (base64) | ✅ Yes |
| `BACKUP_ENCRYPTION_KEY` | AES-256-GCM backup encryption (32+ chars) | `i9j0k1l2...` (base64) | ✅ Yes |
| `ADMIN_PASSWORD` | Initial admin user password | `Str0ngP@ss!` | ✅ Yes |

### 2.2 Optional Variables

| Variable | Description | Default | Required |
|-----------|-------------|---------|----------|
| `CORS_ORIGINS` | Frontend origins for backend CORS | `http://localhost:8080` | ⚠️ Prod |
| `TRUSTED_PROXIES` | Trusted proxy IPs for X-Forwarded-* | `127.0.0.1` | ⚠️ Prod |
| `TZ` | Timezone for containers | `Asia/Tehran` | ❌ No |

## 3. Backend Environment (backend/.env)

**File:** `sana-hrms/backend/.env`  
**Used by:** NestJS application via `ConfigModule`

### 3.1 Required Variables

| Variable | Description | Validation |
|-----------|-------------|------------|
| `NODE_ENV` | Runtime environment | `development` \| `production` \| `test` |
| `DATABASE_URL` | PostgreSQL connection string | `postgresql://user:pass@host:port/db` |
| `JWT_ACCESS_SECRET` | Access token signing key | ≥32 chars, not CHANGE_ME |
| `JWT_REFRESH_SECRET` | Refresh token signing key | ≥32 chars, not CHANGE_ME |
| `BACKUP_ENCRYPTION_KEY` | Backup AES-256-GCM key | ≥32 chars, not CHANGE_ME |
| `ADMIN_PASSWORD` | Initial admin password | ≥10 chars, complexity |

### 3.2 Application Settings

| Variable | Description | Default |
|-----------|-------------|---------|
| `PORT` | HTTP server port | `4114` |
| `HOST` | Bind address | `127.0.0.1` (dev) / `0.0.0.0` (prod) |
| `API_PREFIX` | API route prefix | `api` |
| `SWAGGER_ENABLED` | Enable Swagger UI | `false` (prod) |
| `CORS_ORIGINS` | Allowed origins (comma-separated) | `http://localhost:5183` |
| `TRUSTED_PROXIES` | Trusted proxy IPs | `127.0.0.1` |

### 3.3 JWT Configuration

| Variable | Description | Default |
|-----------|-------------|---------|
| `JWT_ACCESS_EXPIRES_IN` | Access token TTL | `15m` |
| `JWT_REFRESH_EXPIRES_DAYS` | Refresh token TTL (days) | `7` |
| `JWT_REMEMBER_ME_EXPIRES_DAYS` | Remember me TTL (days) | `30` |
| `JWT_REFRESH_GRACE_SECONDS` | Concurrent refresh window | `5` |
| `JWT_ISSUER` | JWT issuer claim | `sana-hrms` |

### 3.4 Security Settings

| Variable | Description | Default |
|-----------|-------------|---------|
| `MAX_LOGIN_ATTEMPTS` | Failed login threshold | `5` |
| `LOGIN_LOCKOUT_MINUTES` | Lockout duration | `15` |
| `PASSWORD_MIN_LENGTH` | Minimum password length | `10` |
| `RATE_LIMIT_TTL_MS` | Rate limit window | `60000` |
| `RATE_LIMIT_LIMIT` | Requests per window | `300` |
| `AUTH_RATE_LIMIT_LIMIT` | Auth requests per window | `5` |
| `DEVICE_CLOCK_SKEW_SECONDS` | Attendance clock tolerance | `120` |
| `ATTENDANCE_TIME_SOURCE` | Time source: `SERVER` \| `DEVICE` | `SERVER` |

### 3.5 Payroll Settings

| Variable | Description | Default |
|-----------|-------------|---------|
| `PAYROLL_CURRENCY` | Base currency code | `IRR` |
| `PAYROLL_DISPLAY_UNIT` | Display unit | `RIAL` |
| `WORKING_DAYS_PER_MONTH` | Working days for OT calc | `30` |
| `DEFAULT_WORK_HOURS_PER_DAY` | Standard work hours | `8` |

### 3.6 Backup Settings

| Variable | Description | Default |

| `PG_RESTORE_PATH` | pg_restore executable path | `pg_restore` |

### 3.7 Seed Settings

## 6. Secret Generation

### 6.1 Automated Generation (Recommended)

```powershell
# Windows PowerShell
pwsh -File scripts/generate-secrets.ps1
```

### 6.2 Manual Generation

```bash
# JWT Secrets (64 chars base64)
openssl rand -base64 48 | tr -d '=+/' | cut -c1-64

# Backup Encryption Key (32+ chars)
openssl rand -base64 32 | tr -d '=+/' | cut -c1-32

# Admin Password (20 chars with complexity)
openssl rand -base64 32 | tr -d '=+/' | cut -c1-20 | sed 's/^/Aa1!/'
```

### 6.3 Secure Distribution

| Method | Use Case |
|--------|----------|
| **GitHub Secrets** | CI/CD pipelines |
| **HashiCorp Vault** | Production secrets |
| **AWS Secrets Manager** | AWS deployments |
| **Docker Secrets** | Swarm mode |
| **1Password/LastPass** | Team sharing |

## 7. Environment Validation

### 7.1 Startup Validation

The application validates configuration on startup:

```typescript
// configuration.ts - requiredSecret()
- Throws if variable missing
- Throws if value is CHANGE_ME
- Throws if length < 32 chars
- Warns if entropy < 3.5 bits/char
- Throws in production if entropy low
```

### 7.2 Validation Commands

```bash
# Validate backend config
cd backend && node -e "
require('dotenv').config();
require('./dist/common/config/configuration').default();
console.log('✅ Configuration valid');
"

# Validate all required vars set
docker compose config --quiet && echo "✅ Compose config valid"

# Check for CHANGE_ME in .env files
grep -r "CHANGE_ME" --include="*.env" . && echo "❌ Found CHANGE_ME" || echo "✅ No CHANGE_ME"
```

## 9. Configuration Drift Detection

### 9.1 Drift Checks

```bash
# Compare running config with .env
docker exec sana-backend env | grep -E '^(NODE_ENV|PORT|DATABASE_URL|JWT_|BACKUP_)' | sort
# Compare with .env file
cat backend/.env | grep -E '^(NODE_ENV|PORT|DATABASE_URL|JWT_|BACKUP_)' | sort

# Check for untracked config changes
git status --porcelain backend/.env frontend/.env .env
```
